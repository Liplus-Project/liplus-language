<subagent-model-policy>

# Subagent Model Policy

- **Every spawn explicitly names `subagent_type`; omission is not a shorthand for the built-in general-purpose agent, it is named as such.** `subagent_type: general-purpose` and an omitted `subagent_type` resolve to the same agent, but only the first states that the role is the host default rather than a role nobody set. This is unconditional across every category below, brake evaluators, delegations, and probe-type rounds alike (#1972).
- **Brake evaluators set `model` explicitly; never let one inherit.** Floor = `sonnet`; which id at or above that floor a given spawn takes is chosen by Selection criteria below, not fixed by the floor. A sub-floor parent otherwise lowers the evaluation floor silently. The brake evaluators are those of brake 1, under `skills/evolution-parallel-agent-eval/SKILL.md`. The floor's detail — `haiku` prohibited, an id that cannot be positively classified as sonnet-class or above falls back to the literal `sonnet` — is in that skill's Constraint.
- **Every other spawn chooses `model` by Selection criteria below; omitting it inherits the parent, and that is the choice to make when the spawn's weight matches the parent's own.** Do not write a parent's id literally: a literal rots the moment the parent tier changes, while omission tracks it without a source edit. No model id is fixed for this category anywhere in Li+ source — the `sonnet` literal above is brake 1's floor and reaches nothing here. The non-brake category is every delegation under `skills/task-subagent-delegation/SKILL.md` (implementation, operations), every bounded read-only investigation under `skills/task-subagent-prompt/SKILL.md` Bounded delegation, and, on Codex, the dialogue evaluator. Together with the brake-evaluator category above, these two categories are exhaustive.
- **For a spawn whose bare behavior is the observation target, set the model at the spawn call; do not give it an agent definition file that pins one.** In Claude Code the agent file body replaces the subagent's system prompt, so a frontmatter `model:` pin cannot be applied without also replacing identity — which mutates the probe-type observation target brake 1 depends on. The per-call parameter changes neither context nor identity. The reason reaches exactly as far as that observation target: the probe-type brake 1 evaluators, whose bare behavior is what the eval reads. It reaches no other Claude spawn. On Codex both judge-type and probe-type brake 1 evaluators select the built-in agent with no definition file, so the prompt carries the judge role when needed and the per-call `reasoning_effort` reaches the bare target unchanged. On Claude Code every definition file left after #1972 is outside the probe target: `low.md` / `medium.md` / `high.md` each pin effort only and name no `model` (see next bullet).
- **`adapter/claude/agents/` holds three files, named by effort, not by role (#1972).** `low.md` / `medium.md` / `high.md` each pin one `effort` value and name no `model`, no `tools`. None carries a role: the body states only that role and procedure arrive in the spawn prompt, and a role fragment must not be written into any of the three — writing one there is the two-copies-of-one-role failure `rules/model/subtractive-structural-beauty.md` Core principle (A) already refuses a place for. What role a given spawn plays is conveyed by the prompt alone, canonically held one place per role: the implementation delegate's literal is `skills/task-subagent-prompt/SKILL.md` Role literal: implementation delegate; the judge-type brake 1 evaluator's is `skills/evolution-parallel-agent-eval/SKILL.md` Constraint: Effort floor. Selecting an effort is choosing `subagent_type: low` / `medium` / `high` at the spawn call; the role text is a separate, mandatory addition to the prompt. The Codex port is unaffected by this split and keeps its per-role `.toml` files, including `adapter/codex/agents/implementer.toml`, `adapter/codex/agents/brake-evaluator.toml`, and `adapter/codex/agents/dialogue-evaluator.toml`. Those files do not set `model_reasoning_effort`: Codex resolves effort per launch, and a definition-file value would override it (#1973).
- **Effort selection at the spawn call**: every delegation under `skills/task-subagent-delegation/SKILL.md` (implementation, operations) and every bounded read-only investigation under `skills/task-subagent-prompt/SKILL.md` Bounded delegation names one of `subagent_type: low` / `medium` / `high` (`adapter/claude/agents/low.md` / `adapter/claude/agents/medium.md` / `adapter/claude/agents/high.md`), selected by Selection criteria below. No role fixes the value, and none of the three is a default to fall back on. A judge-type brake 1 evaluator selects at or above `medium` (`adapter/claude/agents/medium.md`, or a higher effort-named agent), per `skills/evolution-parallel-agent-eval/SKILL.md` Constraint: Effort floor; at or above that floor the selection is the parent's, by the same criteria. A probe-type brake 1 evaluator takes no effort-named agent at all — it spawns as the built-in general-purpose agent and reaches the floor by the parent raising its own session effort instead (same skill, Procedure step 3); this bullet does not reach it.
- **Every Codex spawn explicitly sets `reasoning_effort`; omission is prohibited.** The value is selected per call by Selection criteria below, on the same footing as the `model` axis: no role fixes either one, the implementation delegate and the dialogue evaluator included. A brake evaluator's effort is at or above `medium`, independently of its explicit model floor. Pass only a value exposed by the selected model's enumeration; if the requested value is unsupported, do not guess a fallback. `model` and `reasoning_effort` are independent axes.
- **Deleting a Claude Code role's definition file does not remove it from an already-bootstrapped workspace.** `Li+update.md` Phase 4c performs no stale removal (a user may keep custom subagents not in the adapter source), so `implementer.md` / `brake-evaluator.md` / `dialogue-evaluator.md` deleted from this repository at #1972 stay on disk in any workspace that installed them before this change, inert once no rule, skill, or adapter line names them by that `subagent_type` any more. Clearing them out of an existing `.claude/agents/` directory is a step this repository's own tooling does not take, and is left to the human running that workspace.
- **A definition file's changes take effect on the next spawn, in sessions already running.** No restart is involved and no notice is emitted, so a session whose delegation is in flight is not told. Land a change to these files when no delegation of that kind is running, or tell the sessions that are.
- **The parent session's own tier is out of scope.** `docs/A.-Concept.md` states the documented minimum operating environment; this policy neither raises nor restates it.

<selection-criteria>

## Selection criteria

What the parent reads to choose, on both axes, at every spawn. Role does not enter it: no role fixes a model or an effort, and a value carried over from the last spawn of the same role is not a selection.

- **What the work is made of.** Editing rule prose, or judging what a passage means before changing it, moves the choice up. A replacement whose correct output is fixed before the spawn — a rename applied across known positions, a literal swap — moves it down. An investigation sits where its reading sits, not where its report does.
- **How wide a surface has to be read.** One named file moves the choice down; a set the spawn has to find before it can start moves it up.
- **Which later gate catches an error.** A defect that turns a test or CI red is caught without the spawn's own care, and moves the choice down. A defect only a reader would catch — prose semantics, a cross-reference that still resolves but now points at the wrong thing — has no gate behind it and moves the choice up.

Where the three disagree, the third decides: it is the one that says whether an error survives the spawn. One pass over the three settles the step; this is not a table to fill in before spawning.

</selection-criteria>

<parallel-width-cap>

# Parallel-Width Cap

- **Cap = 5 subagents in flight at once, counted in flight rather than per message.** Five in one message plus five in the next before the first wave returns is ten in flight while every message stays at five. Binding condition: do not launch a new batch until every subagent in the prior batch has completed and reported. Fan-out wider than 5 splits into sequential batches under the same rule.
- **Applies to every parallel delegation routed through `skills/task-subagent-delegation/SKILL.md`, and to bounded read-only investigation fan-out (`skills/task-subagent-prompt/SKILL.md` Bounded delegation)**: cross-parent-issue worktree parallelism and same-parent sub-issue parallelism (both defined in `adapter/claude/CLAUDE.md` Subagent_Delegation), and the investigation fan-out. Exempt: `skills/evolution-parallel-agent-eval/SKILL.md`'s own N / M / P fan-out, separately bounded by that skill's Design Dimensions.
- **This cap is width, not depth.** `skills/task-subagent-prompt/SKILL.md` Bounded delegation governs whether a subagent may spawn its own children. The two axes neither extend nor narrow each other.
- **Nothing enforces this, and 5 is not a measured value.** No hook, counter, or gate exists; the parent applies the binding condition from procedure alone, which `rules/model/subtractive-structural-beauty.md` puts on the replace side of its procedure-vs-structure judgment. Structural enforcement and a derivation for the bound are both open.

</parallel-width-cap>
