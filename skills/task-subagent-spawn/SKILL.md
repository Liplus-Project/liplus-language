# Subagent Model Policy

- **Every spawn explicitly names `subagent_type`; omission is not a shorthand for the built-in general-purpose agent, it is named as such.** `subagent_type: general-purpose` and an omitted `subagent_type` resolve to the same agent, but only the first states that the role is the host default rather than a role nobody set. This is unconditional across every category below, brake evaluators, delegations, and probe-type rounds alike (#1972).
- **Brake evaluators set `model` explicitly; never let one inherit.** Floor and default = `sonnet`; a higher-class id (`opus`, `fable`) may be named but is not the default. A sub-floor parent otherwise lowers the evaluation floor silently. The brake evaluators are those of brake 1, under `skills/evolution-parallel-agent-eval/SKILL.md`. The floor's detail — `haiku` prohibited, an id that cannot be positively classified as sonnet-class or above falls back to the literal `sonnet` — is in that skill's Constraint.
- **Every other spawn omits `model` and inherits the parent; do not write the parent's id literally.** A literal rots the moment the parent tier changes, while omission tracks it without a source edit. The evaluator prohibition above does not reach here: for this category inheriting the parent is the intent. The non-brake category is every delegation under `skills/task-subagent-delegation/SKILL.md` (implementation, operations, bounded read-only investigation). Together with the brake-evaluator category above, these two categories are exhaustive.
- **For a spawn whose bare behavior is the observation target, set the model at the spawn call; do not give it an agent definition file that pins one.** In Claude Code the agent file body replaces the subagent's system prompt, so a frontmatter `model:` pin cannot be applied without also replacing identity — which mutates the probe-type observation target brake 1 depends on. The per-call parameter changes neither context nor identity. The reason reaches exactly as far as that observation target: the probe-type brake 1 evaluators, whose bare behavior is what the eval reads. It reaches no other spawn, and the Codex evaluator has carried its own definition file throughout without the reason applying to it. Outside them a definition file is permitted, and on Claude Code every definition file left after #1972 is outside them: `low.md` / `medium.md` / `high.md` each pin effort only and name no `model`, so none of them displaces a probe-type observation target in the first place (see next bullet).
- **`adapter/claude/agents/` holds three files, named by effort, not by role (#1972).** `low.md` / `medium.md` / `high.md` each pin one `effort` value and name no `model`, no `tools`. None carries a role: the body states only that role and procedure arrive in the spawn prompt, and a role fragment must not be written into any of the three — writing one there is the two-copies-of-one-role failure `rules/model/subtractive-structural-beauty.md` Core principle (A) already refuses a place for. What role a given spawn plays is conveyed by the prompt alone, canonically held one place per role: the implementation delegate's literal is `skills/task-subagent-prompt/SKILL.md` Role literal: implementation delegate; the judge-type brake 1 evaluator's is `skills/evolution-parallel-agent-eval/SKILL.md` Constraint: Effort floor. Selecting an effort is choosing `subagent_type: low` / `medium` / `high` at the spawn call; the role text is a separate, mandatory addition to the prompt. The Codex port is unaffected by this split — it keeps its own per-role `.toml` files (`adapter/codex/agents/implementer.toml`, `adapter/codex/agents/brake-evaluator.toml`), out of scope for it (Master agreement, 2026-09-14; tracked separately from #1972). `adapter/codex/agents/dialogue-evaluator.toml` is out of scope here too, on its own separate axis: it is being removed under #1973, not reorganized under this bullet's split.
- **Effort selection at the spawn call**: implementation, operations, and bounded read-only investigation delegations (`skills/task-subagent-delegation/SKILL.md`) spawn `subagent_type: high` (`adapter/claude/agents/high.md`), unchanged from the prior `implementer` definition's pin. A judge-type brake 1 evaluator spawns `subagent_type: medium` (`adapter/claude/agents/medium.md`) or a higher effort-named agent, per `skills/evolution-parallel-agent-eval/SKILL.md` Constraint: Effort floor. A probe-type brake 1 evaluator takes no effort-named agent at all — it spawns as the built-in general-purpose agent and reaches the floor by the parent raising its own session effort instead (same skill, Procedure step 3); this bullet does not reach it. No fixed role in this spec currently selects `adapter/claude/agents/low.md`; a delegation prompt may still choose it directly when a task's own effort need is genuinely low.
- **Deleting a Claude Code role's definition file does not remove it from an already-bootstrapped workspace.** `Li+update.md` Phase 4c performs no stale removal (a user may keep custom subagents not in the adapter source), so `implementer.md` / `brake-evaluator.md` / `dialogue-evaluator.md` deleted from this repository at #1972 stay on disk in any workspace that installed them before this change, inert once no rule, skill, or adapter line names them by that `subagent_type` any more. Clearing them out of an existing `.claude/agents/` directory is a step this repository's own tooling does not take, and is left to the human running that workspace.
- **A definition file's changes take effect on the next spawn, in sessions already running.** No restart is involved and no notice is emitted, so a session whose delegation is in flight is not told. Land a change to these files when no delegation of that kind is running, or tell the sessions that are.
- **The parent session's own tier is out of scope.** `docs/A.-Concept.md` states the documented minimum operating environment; this policy neither raises nor restates it.

# Parallel-Width Cap

- **Cap = 5 subagents in flight at once, counted in flight rather than per message.** Five in one message plus five in the next before the first wave returns is ten in flight while every message stays at five. Binding condition: do not launch a new batch until every subagent in the prior batch has completed and reported. Fan-out wider than 5 splits into sequential batches under the same rule.
- **Applies to every parallel delegation routed through `skills/task-subagent-delegation/SKILL.md`**: cross-parent-issue worktree parallelism and same-parent sub-issue parallelism (both defined in `adapter/claude/CLAUDE.md` Subagent_Delegation), and bounded read-only investigation fan-out. Exempt: `skills/evolution-parallel-agent-eval/SKILL.md`'s own N / M / P fan-out, separately bounded by that skill's Design Dimensions.
- **This cap is width, not depth.** `skills/task-subagent-prompt/SKILL.md` Bounded delegation governs whether a subagent may spawn its own children. The two axes neither extend nor narrow each other.
- **Nothing enforces this, and 5 is not a measured value.** No hook, counter, or gate exists; the parent applies the binding condition from procedure alone, which `rules/model/subtractive-structural-beauty.md` puts on the replace side of its procedure-vs-structure judgment. Structural enforcement and a derivation for the bound are both open.

</parallel-width-cap>
